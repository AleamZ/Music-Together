## 1. The project
- **Music Together** is a listening room where people play YouTube songs in sync, with chat and lyrics. It has a **game mode**: a 2D pixel world (hall, fishing pond, rice field) where players earn and spend **xu** (in-game coins).
- **Stack:**
  - Next.js 16.2.9 (App Router). It differs from older Next: read `node_modules/next/dist/docs` before using any Next API (`AGENTS.md`).
  - React 19 with the React Compiler lint rules, TypeScript strict, Tailwind v4.
  - Supabase: Postgres, custom session auth through SECURITY DEFINER RPCs, anon key only, no service key.
  - Vitest 4 + jsdom + RTL, pnpm.
- **Repo:** https://github.com/AleamZ/Music-Together. It is public.
- **Owner:** Vietnamese-speaking. Answer in Vietnamese and keep it short. The owner said "chạy đến GOAL … làm theo khuyến nghị": work autonomously and take the recommended (★) option at each decision.

## 4. How the work is done (workflow)
- **Every release goes spec → plan → implementation.**
  - Specs live in `docs/superpowers/specs/`, plans in `docs/superpowers/plans/`.
  - A plan is written with the superpowers *writing-plans* skill. It has a header, Global Constraints (including a SQL check script), and tasks with Files / Interfaces / Steps 1–5: failing test, run, implement, pass, commit.
- **Plan writers validate by building.** They implement every task for real in a scratch git worktree (`mt-*`, branch `wip/*`), one commit per task. Then they replay the plan mechanically on a clean checkout: every Step 2 must fail as written, and every task must end green with the tree identical to its commit. The controller then adopts the validated commits.
- **Reviews and fixes:**
  - Each release gets area reviews, then **one fix round** built from a `fix-findings.md` list.
  - Then a scoped re-review.
  - Then small controller follow-ups.
- **Rulings:** record every decision as "Ruling: X — why — cost if wrong".
- **Commits:**
  - Focused, with a body; every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Commit only when that is part of the task. Push or merge only on the owner's word.

## 5. Hard rules
- **Never run anything against the hosted Supabase database.** The owner runs migrations in the SQL Editor.
- **Local SQL checks** use throwaway clusters only:
  - set up with `initdb -U postgres --auth=trust -E UTF8` on a non-5432 port, with `PGCLIENTENCODING=UTF8`;
  - mirror Supabase's grants (see the plans' check script prelude);
  - never touch an installed Postgres service.
- **Never merge to `main`** before the owner has run the migrations. A v15+ client on `main` without them breaks production.
- **Public repo:**
  - no secrets and no copied or paid assets; all art is original, drawn in code;
  - never type a literal invisible character (zero-width, bidi, odd spaces): write escapes (`"\u200b"` in TS, `U&'\200B'` or ARE escapes in SQL).
- **Never enter passwords or credentials in a browser.** The owner logs in.
- **Migrations are additive and re-runnable:** `if not exists`, `create or replace`, `drop constraint if exists` + `add`, seeds `on conflict do update`. Every function has `set search_path = public, extensions`. Public RPCs are granted to anon and authenticated; private helpers are revoked.
- **Anti-cheat spec §11.3 rules 1–7 bind every later migration.**
  - New game RPCs start with `_ac_play` and do hard checks before any lock; read-only RPCs join the guard allowlist by signature.
  - The `coin_ledger` reason check carries **all** earlier reasons. After 0018 there are 21: daily, song, sell, buy, rent, land_buy, land_sell, land_refund, lease_pay, lease_income, farm_buy, rice_sell, wipe, harvester, produce_sell, card_hold, card_settle, card_buyin, card_cashout, card_refund, critter_sell. v17 adds `rat_sell` and `dog_adopt`.
  - `_ac_holdings` / `_ac_wipe` are re-created from the latest body, keeping every part: cards (`_card_forfeit_all` first), critters.
  - `tests/sql/anticheat-guards.sql`'s loop counts every guarded RPC (52 after 0018).
- **Lock order:** the table or plot row first, then wallets in account-id order. The fish price index row is always locked last, after the caller's wallet. Reads never write the index.
- **Economy:**
  - xu can never be bought or cashed out (Vietnamese gambling law).
  - Prices come from the server, never from client input.
  - Critter and rat prices are `max(1, floor(base × M))`, where M is the fish index at the catch.
- **Client rules (React Compiler lint):**
  - no `ref.current` during render;
  - no synchronous setState in an effect body;
  - no `Date.now` / `Math.random` / `performance.now` in render;
  - canvas hooks take getters;
  - overlays lock the canvas through `lib/game/overlays.ts`;
  - every component or hook test calls `cleanup()` in `afterEach`.
- **Late server answers:** an answer that lands after the player left the field is dropped. Capture the `closes` counter first, then require `canvas()?.mapId() === "field"` when the answer arrives.
- **Copy and numbers:** UI copy is Vietnamese, verbatim from the spec. Numbers use vi-VN. A negative sign is U+2212.
