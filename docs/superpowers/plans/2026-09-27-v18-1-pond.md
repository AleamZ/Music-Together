# v18.1 Ao sống động — plan

Spec: `docs/superpowers/specs/2026-09-27-v18-design.md` §18.1, with the owner's later answers: an overboard costs
hunger −10 and a non-default rod has a 10% chance to be lost; swim mode is visible to others. Rod durability belongs to
18.2 (not built): the "−3 durability" rule is a named no-op seam, `_rod_wear(account, rod, amount)`.

## Decisions
- **Where fishing is allowed:** only the pond map. The hall's river has no fish spot (its dock is a portal to the pond),
  so shore casting is pond-only; the hall stays as it is.
- **Cast tile:** the client sends the 8-px cell (`p_col`, `p_row`) it stands on. The server classifies it with
  `_pond_spot(col, row)`, a copy of the pond geometry (`inPond` oval with the same sine wobble, the platform rects, the
  pond's solids): `'dock'` = a platform cell with a 4-neighbour water cell, `'shore'` = a walkable non-platform cell with
  a 4-neighbour water cell, anything else → `'bad spot'`. The server never knows positions (presence is peer-to-peer), so
  the tile is a claim validated against map data only. `p_col` null (an older client, which only casts from the docks)
  counts as a dock.
- **Shore odds:** the bite wait ×1.5 (after the weather) and the bite chance ×0.4: the cast row gets `bites = random() <
  0.4`. The rarity roll is unchanged, so rare fish keep their relative odds. A cast without a bite ends as
  `lost / no_bite` ("Chẳng có cá nào cắn câu…").
- **Lớn:** stored on the cast at start: `rarity ≥ 3 or weight_g > rod.rating_g` (new column: gỗ 1500 g, tre 3000 g,
  carbon 6000 g; a rod without a rating is never out-weighed).
- **Overboard:** `finish_cast(…, p_hooked default false)`. A reel reported lost (`p_success = false`) with `p_hooked`, on
  a biting lớn cast, after its bite time and before it expired → `lost / overboard`: the fish is gone, `_rod_wear(…, 3)`
  (seam), hunger −10 (after the lazy drain), and `_overboard_outcome(rod, roll)` — pure, so the 10% is testable with a
  fixed roll — decides the rod loss (never `rod_wood`): the inventory row is deleted and the loadout falls back to
  `rod_wood`. The answer carries `overboard: {rod, rod_lost, hunger}` and the vitals.
- **Swim mode (client):** the engine places me on the water cell nearest the bobber, collides against a swim grid (water
  walkable, solids still blocked), speed ×0.5, no prompt / interaction / cast, and ends it when my feet cell is not
  water. Then "ướt" for 4 s (drips). Movement messages carry `sw` (1 swimming, 2 wet; absent = dry), parsed like `v`.
- **Art:** `lib/game/art/swim.ts`, fillRect + drawImage only: the swimmer (sprite rows 0–25, body sunk to the chest,
  a waterline ring, stroking forearms, bubbles, a V wake while moving, 4 directions), the wet drips, the leaping fish
  (600 ms arc, splash + ring at entry and exit). Reduced motion: a still swimmer (no bob, no strokes, a static ring),
  static drip dots, a leap drawn as one still ring.
