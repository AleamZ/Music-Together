# v20.1 plan: fight engine, arena overlay, practice

Spec: `docs/superpowers/specs/2026-09-28-v20-fight-design.md` (§v20.1, global rulings R1–R9, owner rulings at the end).
Branch `feat/v20-fight`. Migration `0048_fight_engine.sql` (private functions only, no tables).

## Rulings made in this plan

- **P1: phases.** The spec's intro / fight / ko / roundEnd / over become four phase ids: `0 intro` (90 frames),
  `1 fight`, `2 end` (the 150-frame pause after a KO or time-up), `3 over`. `step` on an `over` state returns an equal
  copy (the frame counter stops), so replaying past the end is harmless.
- **P2: after the last round.** When round `maxRounds` ends and nobody reached the win target, the fighter with more
  round wins takes the match; equal wins is a draw. (A 1-round-to-win match with five draws is a draw.)
- **P3: move table.** `MOVE_TABLE` holds 8 styles × 18 moves × 32 ints (13 normals incl. the throw, S1–S4, Tuyệt kỹ),
  then 8 style rows × 16 ints. Style traits are baked into each style's normal rows (Taekwondo's longer kicks, Muay
  Thai's armoured HK, Vịnh Xuân's 4-frame LP, Boxing's body punches and jump punches ×1.2, Judo's throw), and chains
  (Karate LP → HP, Vịnh Xuân LP → LP → LP) are style-row fields. v20.1 only lets players use Tự do, but every style is
  in the engine and in the fixtures, so v20.2 adds no engine change.
- **P4: multi-hit moves** scale as one hit (the first hit's combo scale), and only the last hit knocks down.
- **P5: air hits** make the fighter fall, invulnerable; it lands into a knockdown (KD moves) or a 3-frame landing that
  is still invulnerable.
- **P6: strikes beat throws** on the same frame; two throws on the same frame tech each other.
- **P7: `MatchParams` per fighter** carries `style, rank, movesMask, hpPct, bot, en0` and the style stats
  (`atk, def, walk, jump, energy`). `en0` (starting energy, default 0) exists for fixtures, training and bosses.
  `makeParams()` fills the stats from `styles.ts`. The server stores the full params (v20.2).
- **P8: bots.** `step` never runs a bot. `bot.ts` has `stepWithBots(state, a, b)` that replaces a bot side's mask by
  `botInput(state, side)` (bot memory and the PRNG live in the state) and then calls `step`. v20.2's 0049 re-creates
  `_fx_step` with the same prefix (`_fx_bot`). Bot level 9 is the "Bao cát đứng yên" dummy (never acts).
  The v20.1 fixtures have no bot sides (their logs were recorded from bots, then replayed as plain inputs).
- **P9: SQL arrays** are 1-based: SQL index = TS index + 1, for the state and for the move table.
- **P10: fixtures are generated inside Vitest** (`@/` imports need the Vite resolver):
  `scripts/gen-fight-fixtures.ts` exports `buildFightCases()`, and `tests/unit/fight-fixtures.test.ts` checks the JSON
  equals it; `WRITE_FIGHT_FIXTURES=1 pnpm vitest run tests/unit/fight-fixtures.test.ts` rewrites the JSON.
- **P11: text on the arena.** The canvas draws the arena, fighters, sparks, bars, the timer and the big "K.O."
  letters (a small pixel font for digits and A–Z). Vietnamese copy ("Hiệp 1", "Đấu!", "Hạ đo ván!", "Hết giờ!", "Hòa!",
  "3 đòn!", names) is HTML over the canvas, from the pure `hudText(state)`.

## Interfaces

```ts
// lib/game/fight/engine.ts
export type State = number[];                       // STATE_LEN ints; a copy is a rollback snapshot
export interface FighterParams { style; rank; movesMask; hpPct; bot; en0; atk; def; walk; jump; energy }
export interface MatchParams { seed; rounds: 1 | 3; maxRounds; p1: FighterParams; p2: FighterParams }
createMatch(p: MatchParams): State
step(s: State, a: number, b: number): State         // pure; masks are 10-bit
hash(s: State): number                              // FNV-1a u32 over the ints (4 bytes LE each)
runFrames(s, runsP1, runsP2, n): State              // RLE runs, n frames
// field offsets G_* and F_*, fighter(s, side) base, phases PH_*, actions A_*, results
// lib/game/fight/moves.ts  MOVE_TABLE: number[], REC, M_* field offsets, move index constants, moveId()
// lib/game/fight/styles.ts STYLES (id, name, stats), STYLE_IDS, makeParams()
// lib/game/fight/log.ts    encodeRuns, RunRecorder, decodeRuns(runs, limit), runsError(runs, max)
// lib/game/fight/bot.ts    BOT_LEVELS, botInput(s, side), stepWithBots(s, a, b)
// lib/game/fight/input.ts  KEY_BITS, maskFromKeys(keys), padMask(dir), BUTTONS
// lib/game/fight/render/{poses,rig,arena-art,fx,hud,font}.ts
```

SQL (0048): `_fx_moves()`, `_fx_new(jsonb)`, `_fx_step(int[], int, int, int[])`, `_fx_run(int[], int[], int[], int[])`,
`_fx_hash(int[])`, `_fx_runs_decode(int[], int)`, `_fx_runs_error(int[], int)`; all revoked from public, anon and
authenticated. The PRNG is 0046's `_reel_rand` (used by the bot mirror in 0049).

## Tasks

1. **Tables** — `moves.ts`, `styles.ts` (+ `tests/unit/fight-moves.test.ts`: table shape, Tự do has only S1, the
   spec's frame data per normal and special).
2. **Engine** (TDD) — `engine.ts`; `tests/unit/fight-engine.test.ts`: determinism, startup, advantage on hit and block
   (LP +4/0, HP +1/−5, LK +3/−1, HK 0/−7), chip rules, motions (windows, priority, 4-frame buffer), shortcut costs,
   throw and tech, knockdown invulnerability, timer and draw rules, energy gains and costs, snapshot/restore.
3. **Log** — `log.ts`; `tests/unit/fight-log.test.ts`: RLE round trip, decode limits, the error codes incl. rate.
4. **Bot** — `bot.ts`; `tests/unit/fight-bot.test.ts`: level 1 never supers, level 8 beats the dummy within one round,
   deterministic per seed, the dummy never acts.
5. **Fixtures** — `scripts/gen-fight-fixtures.ts`, `tests/fixtures/fight-cases.json` (~40 cases: every style's
   specials hitting and blocked, throws and techs, parry, armour, dodge, anti-air, a double KO, time-up, a 5-round draw,
   the 30 900-frame worst case, bot matches), `tests/unit/fight-fixtures.test.ts`.
6. **SQL mirror** — `0048_fight_engine.sql`; `tests/unit/fight-sql-mirror.test.ts` (the `_fx_moves()` literal equals
   `MOVE_TABLE`, CRLF-insensitive; the constants; the revokes); `tests/sql/fight-engine-smoke.sql` (every fixture
   through `_fx_run` in 300-frame chunks, hashes at every 600th frame and the end; runs decode and errors; one 300-frame
   chunk under 150 ms). Verified on a throwaway PG18 (port 54348, prelude, 0004…0048 in replay order), then deleted.
7. **Render** — `render/poses.ts` (14-joint poses, `poseFor(state, side)`), `render/rig.ts` (the painter: limbs,
   16 × 16 head from the look, uniform colours, belt), `render/arena-art.ts` (practice street at dusk),
   `render/fx.ts` (sparks keyed by frame/fighter/move, rollback-safe), `render/hud.ts` (bars, trail, timer, pips,
   K.O.; `hudText`), `render/font.ts`; `tests/unit/fight-render.test.ts` (every action/move/frame has a pose; effect
   keys dedupe across a rollback; hudText).
8. **Overlay and practice** — `input.ts`, `components/game/fight/FightOverlay.tsx`, `PracticeSetup.tsx`; market
   `punch_bag` interactable (1090, 336), use (1090, 318) facing down, and prop; `InteractKind` `punch_bag`;
   `SHELL_PANEL_OF.punch_bag = "fight_practice"`; GameShell `case "punch_bag"` (every existing case kept, pinned by
   `city-map.test.tsx`); `tests/unit/fight-overlay.test.tsx` (setup options, Esc confirm, key legend).
9. **Preview** — a minimal fake canvas in the scratchpad renders poses and an overlay frame to `fight-v20-1.png`.
10. **Finish** — full Vitest, `tsc --noEmit`, eslint on touched files, localhost:3000 if running; report
