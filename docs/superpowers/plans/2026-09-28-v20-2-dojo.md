Spec: `docs/superpowers/specs/2026-09-28-v20-fight-design.md` (§v20.2, global rulings R1–R9, owner rulings at the end).
Builds on v20.1 (`docs/superpowers/plans/2026-09-28-v20-1-engine.md`, `.superpowers/sdd/v20-1-report.md`). Branch
`feat/v20-fight`. Migrations `0049_fight_matches.sql` and `0050_dojo.sql`.

Owner art directive (2026-09-28, final): fighters keep the v20.1 48 × 64 pose rig; v20.2 adds per-style keyframes on
the rig, and the uniforms are drawn twice — on the rig (v20.1's `UNIFORMS`) and as outfit-slot garments of the world
chibi, so players wear them on the maps. (Two intermediate "switch to the chibi" messages were reversed before any

## Rulings made in this plan

- **P1: the two migrations ship together.** 0049 holds the match tables and the pipeline (`_fx_bot`, `_fx_settle`,
  `fight_push`, `fight_state`, `fight_forfeit`, `fight_wear_uniform`, `fight_unwear_uniform`); 0050 the dojo. A few
  0049 bodies read 0050's tables (`martial_styles`, `martial_enrollments`) or call `_dojo_exam_settle`; plpgsql binds
  them at call time, so 0049 applies cleanly on its own and works once 0050 is in. The owner runs both.
- **P2: the bot mirror adds functions and re-creates none.** `_fx_step` stays 0048's. New private, immutable, SET-less
  helpers (like 0048's): `_fx_bot_script(id)`, `_fx_bot(s, side, m)` (returns the state with the bot's memory and the
  PRNG advanced, plus the mask as element 177 — botInput), `_fx_step_bots(s, a, b, m)` (stepWithBots),
  `_fx_run_bots(s, a[], b[], m)`, `_fx_runs_slice(runs, from, n)` (frames [from, from + n) of RLE runs, 0 past the end).
  `tests/fixtures/fight-bot-cases.json` pins them (player logs against every level 1–8, the dummy, several styles).
- **P3: frame counting.** Frames are numbered from 0 at `started_at`. A log's `frontier` is its last frame (−1: none).
  `sim_frame` is the number of frames the server has stepped; a client's `p_hash_frame` is the same count (the hash
  after that many frames). In a bot match the sim always reaches the player's frontier.
- **P4: retries.** A push whose frames overlap stored ones is accepted when the overlap is identical; any new tail is
  appended. An overlap that differs, a gap, or malformed runs is hard `fight_bad_input`.
- **P5: a hard flag in a bot match** (`fight_bad_input`, `fight_too_fast`) rejects the push and settles the match as the
  player's loss (`end_reason 'forfeit'`), then returns the envelope with the result.
- **P6: the exam match starts 8 s after the kata pass** (`started_at = now() + 8 s`): the kata result card, then the
  3·2·1 countdown. The 60 s no-push rule counts from `started_at`.
- **P7: expiry.** An exam still in `kata` 20 minutes after it started becomes `expired` (a fail: the cooldown applies),
  lazily. An exam in `spar` follows its match (the match's abandon rule settles it).
- **P8: exam fighters.** The player fights with the exam's style at the current rank's unlocks (the uniform must be
  worn at kata submit, else `'no uniform'` and nothing is consumed); the master bot has the target rank's unlocks and
  the belt's bot level, HP 100 %, 3 rounds (best of 3), maxRounds 5.
- **P9: vitals cost.** Rounds played = the round in progress or last played (`G_ROUND`, ≥ 1): 2 hunger and 3 thirst
  each, applied at settlement (never below 0; a fight never faints anyone).
- **P10: `fight_superhuman` evidence** lives in `fight_logs.ac int[]` = {bot's last move start frame, fast reactions,
  busy frames, flagged}. A fast reaction: a new block (Đỡ or back) or a new attack button 1–4 frames after the bot
  starts a move. Busy: a push of ≥ 60 frames with more than 18 mask changes per 60 frames adds its frames, else resets;
  ≥ 600 flags. Either flags once per match (soft).
- **P11: honest logs never trip `rate`.** The client limits its own mask changes to 20 per 60 frames before the sim
  sees them (`RateLimiter` in `log.ts`), so what it pushes always passes `_fx_runs_error`.
- **P12: the client never runs ahead of the clock.** Its frame count stays ≤ (server now − `started_at`) × 60 (the
  server allows 60 more), from the offset of `server_now_ms` in RPC answers.
- **P13: the world chibi's uniform** draws the belt (armband, sash, waistband) in the style's rank-0 colour: the look
  does not carry the rank. The fight rig draws the real rank colour (v20.1), with Muay Thai's mongkol and Boxing's
  champion buckle at rank 4.
- **P14: uniforms in the catalog.** `vp_*` rows: slot `outfit`, unisex, price 0, not starter, sort 900–906. The store tab
  hides them (`filterStoreItems`), the wardrobe shows them; the sell and give buttons are not offered for them, and the
  three fashion RPCs refuse them with `'uniform'`.
- **P15: practice style.** Practice uses the worn uniform's style at its rank when enrolled, else Tự do. The dojo's
  "Luyện tập" button opens practice (it needs the uniform on; "Mặc võ phục" first).
- **P16: wear / unwear.** `fight_wear_uniform` remembers the current outfit in `fight_profiles.prev_outfit` only when
  it is not a uniform; `fight_unwear_uniform` restores it when still owned (else no outfit) and clears it.
- **P17: kata.** `kataChart(seed, target)`: notes and ticks per beat from the belt row; the first note at tick 180; for
  each later note (target ≥ 3) one roll `u % 100 < 20` makes the gap a half beat; each note one roll `u % 8` for the
  lane, bumped `+1 mod 8` when it would be the third in a row. Rolls are mulberry32 (`rand32` / `_reel_rand`) from the
  seed, gap roll before lane roll. Judging goes press by press: the nearest unjudged note of that lane within 9 ticks
  (the earlier on a tie) — ≤ 4 Hoàn hảo 2 points, else Tốt 1 point; no such note costs 1; the total is floored at 0
  at the end. Pass: `points × 100 ≥ pass_pct × 2 × notes`. The chart's length is the last note's tick + 30, which
  bounds the press ticks and the pacing (0.95 × length / 60 s after `dojo_exam_start`).
- **P18: server copies.** `martial_styles.sort` is the engine style id (1–7); `dojo_state` returns the style and belt
  tables; a unit test pins the 0050 seeds against `lib/game/fight/dojo.ts`.
- **P19: answers carry `server_now_ms`** (`dojo_state`, `dojo_exam_start`, `dojo_kata_submit`, `fight_push`,
  `fight_state`) for the clock offset.
- **P20: per-style art.** Each style gets 2 stance frames (idle) and 3–4 keyframes per special (startup, active,
  recovery; the super's own), as rig pose specs in `render/style-poses.ts`; `poseFor` picks a style key by
  `(action, move, frame)` exactly as before, so a rollback still redraws correctly.
